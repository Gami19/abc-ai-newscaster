## Step 2：アーキテクチャ設計（採用理由付き）

---

### 設計の大方針

本アーキテクチャは以下の**3つの制約**から逆算して設計しました。

```
① イベント期間限定（5日間）→ 運用コストを最小化
② 小学生ターゲット      → 体験レイテンシを最小化（待たせない）
③ 4日間でプロトタイプ   → 実装コストを最小化
```

> **「必要十分な技術を、最短で動かす」** が設計の核心

---

### 採用理由：フロントエンド

#### ✅ Next.js (TypeScript)

```
なぜ Next.js か？
├── Vercelへのデプロイが1コマンドで完了
│     → インフラ構築に時間を使わない（4日間の制約）
├── App Routerによるページ遷移が体験フローと1:1対応
│     → 入力→撮影→生成→プレビュー→QR の5画面
└── TypeScriptで型安全
      → 少人数開発でのバグを事前に防ぐ
```

#### ✅ Canvas API（合成処理をフロントで行う）

```
なぜサーバーで合成しないのか？
├── 顔写真をサーバーに送らずに済む
│     → 個人情報（顔）の外部送信リスクをゼロに
├── 合成処理のレイテンシをなくせる
│     → サーバーラウンドトリップ分の待ち時間が消える
└── Canvasはブラウザ標準APIで追加ライブラリ不要
      → 実装コスト削減
```

---

### 採用理由：バックエンド

#### ✅ FastAPI (Python)

```
なぜ FastAPIか？
├── OpenAI SDK・ffmpegとの親和性が高い
│     → Pythonエコシステムで全て完結
├── 非同期処理（async/await）が標準サポート
│     → GPT-4o・TTSの並列呼び出しが容易
└── 自動ドキュメント生成（Swagger UI）
      → チーフとの仕様共有が楽
```

#### ✅ Lambda（サーバーレス）

```
なぜEC2・ECSではなくLambdaか？

【イベント特性との相性】
├── 平日昼間だけ負荷が集中し、夜間はほぼゼロ
│     → 常時起動のEC2は無駄なコストが発生
├── リクエスト数に応じた自動スケール
│     → 5台同時利用のピーク時も対応可能
└── 5日間限定イベントなので
      → 使った分だけ課金のLambdaが圧倒的に安い

【開発コストの観点】
└── インフラ管理（OS・ミドルウェア更新）が不要
      → 4日間をコード実装に集中できる
```

---

### 採用理由：AI選定

#### ✅ GPT-4o（原稿生成）

```
なぜGPT-4oか？
├── 子供向け・教育的・安全なコンテンツ生成の実績
│     → system promptで確実にトーン制御できる
├── 150字程度の短文生成なら応答速度が速い（約3秒）
│     → 体験の待ち時間に収まる
└── 他モデル比較
      Gemini → SDK切り替えコストが発生
      Claude → 日本語自然さは同等だがOpenAIで統一した方が実装シンプル
```

#### ✅ OpenAI TTS（音声合成）

```
なぜOpenAI TTSか？
├── GPT-4oと同じSDKで呼び出せる
│     → バックエンドのコード量を最小化
├── 日本語の自然さが高い
│     → 子供が聞いて楽しい体験品質を確保
└── AWSのPollyと比較して
      → 追加サービス設定が不要・すぐ使える
```

---

### 採用理由：インフラ

#### ✅ S3 + CloudFront（動画配信）

```
なぜS3 + CloudFrontか？
├── 5万人が動画をQRでDLする負荷に耐えられる
│     → CloudFrontのエッジキャッシュで分散配信
├── 署名付きURLで期限付きアクセス制御
│     → 動画の無断拡散・永続保存を防止
└── ライフサイクル設定で7日後自動削除
      → 個人情報（顔入り動画）の管理義務を最小化
```

#### ✅ Vercel（フロントホスティング）

```
なぜVercelか？
├── Next.jsの開発元であり最も最適化されている
├── GitリポジトリへのPushで自動デプロイ
│     → 4日間の開発中に何度でも即座に反映可能
└── HTTPS・CDNが標準で付属
      → セキュリティ・パフォーマンス設定が不要
```

---

### アーキテクチャ選定の全体まとめ

| 決定 | 採用理由の核心 |
|------|-------------|
| フロントでCanvas合成 | 顔写真をサーバーに送らない（プライバシー最優先） |
| Lambdaサーバーレス | イベント限定＝コスト最適・自動スケール |
| GPT-4o + TTS統一 | 同一SDKで完結＝実装コスト最小 |
| S3 + CloudFront | 5万人DLの負荷分散＋自動削除でプライバシー管理 |
| Vercel | 4日間で何度でも即デプロイできる開発速度優先 |

> **全ての選定に共通する思想：「イベント5日間・開発4日間」という制約の中で、体験品質とセキュリティを落とさずに最速で動かす**
